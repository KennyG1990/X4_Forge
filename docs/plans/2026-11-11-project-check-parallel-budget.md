### Decisions and implementation units

1. **Versioned durable ownership first.** Extend the existing coordinator/worker journal to a bounded set of per-command guard rows. Each row retains exact registry identity, claim/backend instance and PID, run, binding/command/launcher hashes, Job name and helper PID. Keep at most32 admitted guards for a run and at most the approved active budget. Each slot remains occupied until the exact helper has reported durable drain and its exit is confirmed. Distinct guard identities cannot replay or replace each other.
2. **Fail-closed protocol cutover.** Use a new coordination schema/worker protocol, with explicit empty/quiescent schema2 migration. Do not silently add a table that old cached readers ignore. Test an already-open legacy connection: its old read/insert/arm SQL must refuse after cutover, so it cannot acquire a source while new child guards exist. A schema change must structurally invalidate old claim operations; merely checking the version once in a new constructor is insufficient. Nonempty/live/unknown legacy registries must refuse migration without deleting rows or workers. A migration blocked on a live guard is an unavailable state, not permission to clear it.
3. **Budget through existing owner approval.** Add optional root maxParallelChecks, integer1..4 initially. Absence remains serial and byte-compatible for legacy proposal/setup/receipt preparation. Explicit budgets are part of the captured setup and owner review hash; changing the budget requires fresh approval and proof. Reject invalid/over-cap/fractional/string/null values before preparation/spawn. The limit controls concurrent check attempts, not threads/cores or total RAM. Existing one-suite-per-service-instance admission remains.
4. **Bounded scheduling under one source claim.** Dispatch checks in declaration order up to the approved limit. On the first observed non-passing/unready/unconfirmed/error result, stop admitting new checks and drain every already-started attempt before returning or throwing. Preserve per-check timeout, output caps, workspace/actor, approval/artifact checks and exact command IDs. Store completed children in declaration order regardless of completion order, so canonical outcome/reopen hashes agree. Never use early Promise.all rejection to release ownership while another worker is live.
5. **Versioned multi-result evidence.** Extend suite summary/report policy explicitly for parallel outcomes and the reviewed budget; preserve legacy serial readers/receipts. A parallel failed suite may contain several failed/incomplete children but never earns coverage. Incomplete cleanup dominates a confirmed failure. Named attempted, refused-before-start and never-started counts must be truthful. Bind the declared policy into the reviewed authority and verify it when reopening, rather than trusting an unbound metadata hint. Schema/metadata changes require their own strict reader tests; do not globally relax the legacy exactly-one-failure invariant.
6. **Integrate all existing consumers.** Proposal/project validation must expose the declared budget without executing checks. Owner review/setup/approval must capture it; async runs and both native deploy aliases must consume the same suite proof. Successful proof still requires every exact current command to pass with unchanged artifact/approval and all workers drained. Installed owner UI, actual consumer timing and public delivery remain separate required layers.
