## Acceptance

1. Add a read-only bounded reader in `src/server/gameLogLoadEvidence.ts` for the legacy query. Retain at most 16 cursors with file identity and small continuity anchors, one latest explicit load record and bounded partial-line handling. Keep recent reads at 256 KiB and historical cold or catch-up reads at 16 MiB. Retain no log text. Reuse a matching append stream and invalidate observed discontinuities, rotation, truncation and same-size rewrites. Continuity anchors assume X4's append pattern and do not verify arbitrary changes to every previous byte.
2. Match the exact extension identity in the recognized general-channel load line. Keep an attributed engine fault with that load until a newer matching load. Exclude signature notices and require an engine-shaped error beyond an isolated punctuation marker. Cue or marker activity can establish that the mod was seen without proving a clean load. Expose the scan window and reason when evidence is incomplete. Preserve existing recent diagnostic fields and meanings.
3. After successful native deployment, use the runtime adapter's matching deploy token, segment identity, log path and EOF when available. No prior byte may establish a post-deploy load. If a known deploy lacks a usable fence, report limited evidence. The legacy endpoint cannot reconstruct a deploy after process exit without workspace authority. A recognized log record proves what the current log says and carries no exact-artifact claim.
4. Replay the paired exact current bundles on a private backend and synthetic log. Cover the 12 MiB rollover, cold and warm reads, bounded append, later load, attributed fault, authored marker and lookalike exclusions, partial and oversized lines, scan cap, rotation, truncation and rewrite. Run a fresh guarded v101 scratch deployment with exact bytes and durable receipt, then verify pre/post-EOF behavior. Run the log and runtime freshness oracles, typecheck, writer audit, diff and normal precommit. Keep evidence in private QA. Record the recognized fixture format as isolated evidence. Rollback is the bounded reader, adapter accessor and server response diff.

Live work is active. Tests use owned scratch roots, no desktop or game input, and no live logs or mod files. The reader adds no network, credential, permission or write surface.

Fresh review added four negative controls before final qualification. Historical load IDs use the exact requested ID or the recorded canonical ID and selected folder from a matching native deploy. The existing recent diagnostics keep their legacy aliases. Historical faults require an owned extension path or an exact engine script identity and exclude tagged authored messages. An incomplete line or skipped record yields unknown until coverage recovers. Repeated polling after a lost deploy fence cannot turn the observation point into a deploy EOF. If recent activity is visible without a proven load, label it as recent-log evidence.

The first precommit run found the new reader absent from the audited transitive source list. Update that list for the imported reader only, preserving all route and capability dispositions. Rebuild and rerun the exact HTTP proof and normal gate with that manifest.
