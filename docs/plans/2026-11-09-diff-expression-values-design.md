## Reconcile and design

`lintScriptExpressions` in src/lib/mdPitfallLints.ts currently traverses XML attributes only. `runProjectValidation` already composes canonical base/DLC content using `resolveEffectiveReferenceDocument` and `simulateXmlDiff`, but post-apply validation is XSD-only. Graphify shows the same simulator is reused by reference preview, overlays and bulk transforms; preserve their default result/behavior. No second composer or selector parser is needed. Existing source-role recognition and `lintMdExpressionRules` remain the rule authority.

Three approaches were compared. Parsing selector spelling alone is small but can invent expression roles, lint skipped conditions and reject transient values later removed. Checking the final serialized document finds the malformed value but loses original patch provenance and can report unrelated base defects. The selected design extends the existing simulator with **opt-in attribution of final literal attribute assignments**. It records the actual selected Attr object after successful replace/add, its owner/attribute role and original parsed operation payload. Later writes replace its attribution. Only current attributes attached to the final document survive; discarded attributes/subtrees and failed/false operations cannot contribute. Consume this metadata only after successful complete simulation.

Capture original operation text/CDATA source pieces before serializer/wrapper conversion, because those conversions lose lexical offsets. Map the shared grammar's decoded UTF-16 offset through original pieces/entities to one-based authored patch coordinates. DOM operation locations govern attribution, not the existing regex that can count comment decoys. Preserve ordinary direct-attribute behavior. Coalesce an identical authored token/operation/role finding when one XPath targets multiple equivalent attributes; preserve distinct authored operations/roles and stable identities.

The project validator opts into this metadata and reuses the exact expression-role and rule logic for final MD/AI targets. Non-expression attributes are not linted as expressions. An unavailable canonical parent/failed selector remains explicitly unavailable in the existing diff result; do not guess role or claim those checks complete. Availability propagation must be reconciled before wiring success decisions. No new visible panel is proposed; existing diagnostic and native refusal paths are reused.
