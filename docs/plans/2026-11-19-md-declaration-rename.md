# Safe rename for authored Mission Director declarations

PARTIAL under [#74](https://github.com/KennyG1990/X4_Forge/issues/74). The public 0.0.86 release finished at `f7797d34fefa5ca57aea951d387290d7d32343e9`. The private source projection reconciles to its 1,161 tracked files before applying the rename candidate.

## Reconcile

Forge already resolves literal cue and library identities when opening definitions and finding references. `vscode-extension/src/langNav.ts` uses `shared/mdDeclarationResolution.ts` and `shared/xmlSourcePosition.ts`. The provider reads the live editor buffer and bounded sibling files. The search of the committed extension found definition and reference providers and no rename provider or `WorkspaceEdit` application. Keep those read-only operations working with incomplete files. Rename needs a stricter inventory because a skipped file can contain a use.

The [existing ship and weapon XML map](https://github.com/KennyG1990/X4_Forge/issues/100) already traces macro, component, and bullet links and has API and MCP entry points. A prior [compiled release replay](https://github.com/KennyG1990/X4_Forge/issues/119) traced a mod ship through its game weapon references. Asset rename and effective patch composition remain under their existing scopes. The [CodeSense marketplace documentation](https://marketplace.visualstudio.com/items?itemName=X4DevTools.x4codesense) provides the behavior benchmark. Forge uses its own parser, positions, and declaration resolver.

## Acceptance

- Rename a uniquely resolved authored MD cue or library and its supported literal uses within one mod. Preview the exact declaration, file and ranges. Preserve qualifiers, surrounding whitespace, quoting, and every byte outside the replacements. Preserve a library instance's own name when changing its `ref`.
- Capture immutable document and inventory facts for preview and verify them before applying. Give unsaved buffers precedence. Check physical project containment and file identity on each target. Refuse incomplete, malformed, duplicate, or over-budget inventory, paths through links, stale input, and cancellation. Expose the exact reason in the editor.
- Resolve the edited snapshot before applying. Renamed uses must still reach the selected declaration and other modeled bindings must stay the same, including unresolved ones. Refuse scope collisions, reserved names, and evidence of a target use in an unsupported expression, patch, or external consumer. Treat opaque coverage as unresolved before offering an apply.
- Keep preview read-only. Apply one host edit with Undo, or refuse when the final recheck detects a changed input. [VS Code 1.85's RenameAdapter](https://github.com/microsoft/vscode/blob/1.85.0/src/vs/workbench/api/common/extHostLanguageFeatures.ts#L719) converts the provider result without document versions. The Forge command loads its edit targets and rechecks the reviewed input immediately before calling [the public apply API](https://github.com/microsoft/vscode/blob/1.107.0/src/vs/workbench/api/common/extHostBulkEdits.ts#L25-L33). It includes a version check on open sibling buffers even when the preview has no replacements in them. Entry metadata keeps the host's active-editor minimization from stripping the expected version. Closed-file changes and new directory members after the final disk check remain a release qualification boundary. [Host task validation](https://github.com/microsoft/vscode/blob/1.107.0/src/vs/workbench/contrib/bulkEdit/browser/bulkTextEdits.ts#L232-L326).
- Keep the rename planner available to the existing agent parity owner [#19](https://github.com/KennyG1990/X4_Forge/issues/19). Route a future API/MCP apply through the same scope, snapshot, and approval rules. An API consumer needs an explicit answer when the editor has unsaved state it cannot see.

Cover local and cross-file references, a library instance, unrelated same-name declarations, comments, entity-encoded names, single quotes, BOM, CRLF, and open buffers. Also check malformed sibling coverage, duplicate identities, same-size disk edits, document changes after preview, link boundaries, cancellation, and unchanged bytes on refusal. Require the same edit and Undo in the isolated installed host before public delivery. Keep the fixture in the existing private projection and retire its scratch outputs once its compact receipt is saved. Roll back an applied scratch edit with the host's Undo. Revert the isolated implementation if it cannot meet the coverage or freshness checks.

The source candidate adds **X4 Forge: Rename Mission Director Symbol**. The preview lists the exact source ranges and replacements for one unpacked mod's MD folder. Each edited document is loaded before confirmation. The command rechecks disk fingerprints, paths, file membership and open documents, then delegates one text-only edit to the editor. The current scope rejects MD patch files, nested paths, dependency overlays, packed sources and unsupported expressions that could change the selected name. Other extensions, expression rewrites and patch selectors remain under the initiative.

The isolated CodeSense 1.2.0 server advertised prepared rename and indexed the two fixture scripts with the unpacked X4 schemas. Forge matched all four replay cases, including the same four edit ranges for both qualified and entity-encoded selections and zero edits for comment and quoted-string selections. The final editor type check and 40 navigation and rename checks passed. They cover library instances, BOM, CRLF, newly captured unresolved uses, ambiguous names and schema-documented prose attributes. An earlier host shim passed 13 cases for dirty buffers, same-size disk changes, added files, links, cancellation, and a simulated host refusal.

The actual editor applied all four replacements in one edit and Undo restored both files. Saved bytes stayed identical. Cancellation, stale target and stale non-target buffers refused before the command dispatched edits. An unchanged sibling stayed clean and retained its version, even when it was active at apply. The host loaded the exact candidate shell and used scripted prompt responses. Its private desktop, process tree and discovery checks passed.
