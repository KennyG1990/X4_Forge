# A15 owner credential rotation in Dev Forge

Status VERIFIED for the isolated Dev API. Full lane under [issue #61](https://github.com/KennyG1990/X4_Forge/issues/61), which remains PARTIAL. Baseline is the clean isolated Dev checkout `aa605009ea00337a2627e22eb4b1f7dbe7ee56ec`. Owner approval uses an independently trusted launch policy, a signed exact review, and a version 2 activation pointer. The baseline pointer parser conflated a structurally valid prior policy with malformed authority. A newly pinned owner could not open a fresh approval review after a legitimate launcher rotation.

Reuse `projectCheckNativeProof.ts`, `projectCheckOwnerEnrollment.ts`, the two existing owner routes and the existing source and approval locks. Separate pointer integrity from whether it is active under this policy. A well-formed prior pointer is eligible for signed replacement and supplies no active approval to run, coverage, deploy or revoke. Bind the exact prior pointer bytes to the review. Recheck them under the existing locks and at the atomic replacement. A failed confirmation or activation preserves the previous pointer. Existing native execution and proof continue to require a current pointer and exact approval. Legacy or malformed records stay fail closed.

Prove the old refusal on a disposable signed credential over the private HTTP entry points. On the candidate, prove fresh B approval after A, no writes on stale challenges, changed prior pointer or malformed records, a fresh B run and committed native scratch deploy, and fresh A approval after a committed B when the launcher returns to A. A B launch without signed activation leaves A's last approved pointer intact, so reverting the trusted launcher before B approval restores the previous configuration. A durable policy epoch for startup alone is outside this unit. No OS credential store, launcher, profile, real game or public capability changes.

Use the existing private Windows signed replay and owned listeners, the approval/setup selftests, typecheck and normal precommit. Keep exact bundle hashes and HTTP evidence in the private QA directory. Rollback is the isolated base commit. Real device provisioning, rendered review and installed recovery stay separate. No capability-map delta is expected. This change reuses the existing durable pointer and its atomic writer.

## AAR

Reuse the existing signed ceremony and native proof replay. The baseline exposed one guard serving two different purposes. Separate activation eligibility from integrity so the guard can preserve trust while allowing recovery. Bind exact prior bytes even when the old approval is inactive. Recovery still depends on the local launcher pin and a successful fresh signed confirmation. Retain those as distinct proof steps when adding installed owner onboarding.
