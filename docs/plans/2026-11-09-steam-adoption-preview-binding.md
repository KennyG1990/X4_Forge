## Scope and acceptance

- Reproduce a stale confirmation against two identical, legitimate authoring imports that share an artifact folder basename and therefore a Steam report. Prepare, Verify and Preview A. Prepare and Verify B with the same Workshop ID and staged bytes, then replay A's confirmation. Separately test a fresh Verify with new Workshop-managed bytes and an unchanged source and ID.
- Reuse the existing coordinated Prepare, Verify and Adopt routes, physical source guard, and native deployment's deterministic binding convention. Add one preview digest over the exact verified report, physical authoring file identity, source bytes and staged bytes. Require the digest on Apply after the existing source-hash and Workshop-ID checks. A missing or changed binding requires a fresh preview. Avoid persistent approval state, alternate writers, release repinning, live access, real Workshop activity and changes to native Deploy.
- Carry the digest through the strict HTTP body contract and Release Center. Only a fresh READY_TO_ADOPT response can be confirmed. Keep old eligible reports usable through fresh Preview. A legacy Apply with only source hash and Workshop ID must refuse, because it cannot distinguish two reviewed destinations.
- Verify the old routes reproduce the wrong write and the candidate returns an explicit 409 while both sources, the current staged artifact and the report retain exact bytes. Verify a renewed confirmation writes only the currently displayed authoring manifest. Cover malformed and missing binding, unchanged repeated preview, and an identical-byte source replacement if fixture identity is controllable.
- Evidence uses the owned scratch HTTP replay, contract selftest, TypeScript, precommit and diff review. Maintain the established route and headless UI tests. Run eligible focused headless UI coverage only on an isolated browser and scratch runtime under the machine constraint. Exact installed rendering and package verification remain separate. Revert this bounded commit if needed. No new route, writer, network surface or capability is planned.
